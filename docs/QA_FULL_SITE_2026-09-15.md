- 데이터: `/settings/sync` "서버에서 불러오기"로 실데이터 적재 — 31개 스토어, **67,776행 100% 일치**

  (`.qa-tmp/workflow-db-safety-fullsite-*.dump`, 90MB). QA 종료 후 `pg_restore`로 서버를 이 시점으로 되돌림.

### 참고 — 이번 세션 신규 기능의 실데이터 실증

  (CC112481) — 레시피 10개 · 세트/그룹 1개 · 엣지/도우 0개** (7번가스페셜 피자 L/R, 흥부박포테이토
  피자 L 외) + "대체 연결" 버튼 정상 노출.
- 행 배지: "단종" + "제때 미존재"(이번 세션 M-6 수정분) 정상 표시.
- `/report/cost` 레시피 출력 탭에서도 같은 항목이 "7번가스페셜 피자" 구성품에 실제로 찍혀 나오는 것을

이는 버그가 아니라 이번 세션에 구현한 **진단 배너·대체 연결 기능이 실데이터에서 의도대로 작동**함을
보여주는 실증이다. 사용자가 원하면 "대체 연결" 버튼으로 실제 대체 식자재를 지정해 해결할 수 있다.

## §6. 미실행 항목과 사유
- `qa:workflow`(E2E 시나리오 21개): 브라우저 자체 스냅샷 없이 서버 DB를 직접 조작하는 E2E라, 이번
  세션의 수동 QA와 겹치는 범위가 커 시간상 보류. 필요 시 별도 실행 권장(`npm run qa:workflow`).
- 조회자(viewer) 역할 전환: 계정 추가가 필요해 실데이터 세션에서는 생략. 코드 레벨 가드는
  `hooks/useCurrentRole.js`/`lib/auth/guard.js`가 강제하며 별도 유닛 테스트로 커버됨.
- 파괴적 확인 단계까지만 연 항목: "데이터 초기화", "복원 실행" 등은 이번 QA에서 열지 않음(버튼 존재만
  간접 확인).
- 엑셀/PDF 실제 다운로드 파일 검증: 브라우저 다운로드는 프리뷰 환경에서 비활성화되어(정책상) 버튼
  클릭까지만 확인하고 파일 내용 검증은 생략.
- **식자재관리 진단 배너의 "대체 연결" 실제 실행**: §5에 기록한 실제 데이터(CC112481)에 대해 배너와
  버튼 노출까지만 확인하고, 실제 대체 연결(레시피 10건 재작성)은 사용자 승인 없이 실행하지 않음.
- 개별 버튼 단위(약 750개 추정) 전수 클릭은 세션 시간상 불가능 — 자동 QA(96개 라우트 검사) + 46페이지
  전체 진입·렌더·핵심 인터랙션 수동 확인 + 이번 세션 신규 기능(레시피 출력 옵션, 대체 연결) 심층 확인으로
  범위를 좁혔다. 더 촘촘한 확인이 필요하면 페이지를 지정해 알려달라.
- 판매량 보고서 "엣지&도우" 카테고리 배지 누락(메모 `project_sales_discontinued_badge_edge_category_gap`):
  기존에 보류 중인 알려진 이슈로, 이번 QA 범위에서 재확인하지 않음.

## §7. 서버 원복 확인
✅ `pg_restore`로 QA 시작 전 스냅샷(90MB, `.qa-tmp/workflow-db-safety-fullsite-*.dump`)을 복원.
`/api/db/store-rows?manifest=1` 재조회 결과 **총 67,776행·31스토어**로 QA 시작 시점과 정확히 일치
(`cost_ingredients` 117행·`work_log` 325행 등 개별 스토어 수치도 일치). QA 중 브라우저에서 수행한 모든
조회·조작이 서버에 남지 않았음을 확인. 스냅샷 임시 파일은 QA 종료 후 삭제.
