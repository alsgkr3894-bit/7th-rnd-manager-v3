# 다른 PC에서 접속하게 할 때 필요한 것 (미적용)

2026-11-27. 지금 사이트는 **이 PC 안(127.0.0.1)에서만** 열리고 자동 시작도 그렇게 돼 있어, HTTPS는
설치하지 않았다(결정). 다른 PC에 열기로 하면(`npm run site:start:lan`) **그 전에** 아래를 해야 한다.
HTTP로 열면 같은 네트워크에서 화면 내용과 로그인 쿠키를 볼 수 있다.

## 열기 전에 알아 둘 제한

- 최초 비밀번호 설정과 비밀번호 변경은 운영 PC에서만 된다(HTTP에서는 거부).
- 로그인 실패 제한은 접속한 곳을 나누지 않는다. 다른 PC에서 5번 틀려도 15분 동안 모두 로그인하지 못한다.
- 서버는 `Host`·`Origin` 헤더로 출처를 확인한다. 이는 바깥 웹페이지의 요청을 막는 장치이지, 네트워크에
  접근한 사람을 막는 장치가 아니다. 막는 것은 로그인이다.

## 절차 (인증서와 Windows 설정을 바꾸는 단계는 직접 실행)

1. 운영 PC의 고정 IP 또는 이름을 정한다.
2. 앞단 프록시(Caddy 등)를 설치해 `https://<이름>` → `http://127.0.0.1:3000`으로 넘긴다. 사이트는 계속
   127.0.0.1에만 연다.
3. 프록시의 내부 인증 기관(CA) 인증서를 접속할 PC마다 "신뢰할 수 있는 루트 인증 기관"에 등록한다.
4. `.env`에 `RND_ALLOW_LAN="1"`, 이름으로 접속하면 `RND_ALLOWED_LAN_HOSTS="<이름>"`.
5. 방화벽은 프록시의 443 포트만 사내 네트워크에 연다.
6. 코드 쪽 남은 일: 프록시가 보내는 `X-Forwarded-Proto`를 신뢰해 쿠키에 `Secure`를 붙이고, HSTS 헤더를
   추가해야 한다. 지금은 요청 주소의 프로토콜만 보므로 프록시 뒤에서는 `Secure`가 붙지 않는다.
7. 다른 PC에서 로그인, 화면 이동, 인쇄, 엑셀 올리기를 확인한다.
