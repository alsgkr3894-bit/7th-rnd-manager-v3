# 핵심 업무 흐름 E2E QA (P1)

작성일: 2026-06-17

`SITE_QUALITY_IMPROVEMENT_PLAN.md` P1(핵심 업무 E2E)을 위한 브라우저 멀티스텝 QA. smoke/runtime QA(읽기 전용 라우트 순회)와 역할이 다르다 — 실제 사용자의 긴 업무 흐름을 단계별로 구동·검증한다.

## 실행

```bash
npm run qa:workflow      # dev 서버(localhost:3000)가 떠 있어야 함
```

- `scripts/workflow-qa.mjs` — Playwright 하니스(시나리오 러너). `newAuthedContext`로 로그인 우회.
- `scripts/workflow-qa-utils.mjs` — 순수 헬퍼(시나리오 통과 판정·요약·스텝 출력·백업 형태 검증). 단위 테스트 `__tests__/scripts/workflow-qa-utils.test.mjs`.
- 종료 코드: 전 시나리오 통과 0, 하나라도 실패 1.

## 구현된 시나리오 (3)

| # | 시나리오 | 검증 내용 | 부작용 |
|---|---|---|---|
| 1 | 백업 → 복원 미리보기 | 백업 다운로드 캡처 → 파일 유효성(stores 객체) → 복원 페이지 업로드 → 미리보기(복원 실행 단계) 렌더 | 없음(미리보기까지만) |
| 2 | 노트 작성 → 목록 반영 | /note/write 필수항목 입력 → 저장 → /note 이동 → 목록에 표시 | 생성 후 IDB 정리 |
| 3 | 메뉴 마스터 등록 → 목록 반영 | 메뉴 추가 모달 → 코드·이름 입력 → 저장(모달 닫힘) → 목록에 표시 | 생성 후 IDB 정리 |

각 스텝은 성공/실패와 사유를 기록하고, 실패 시 "최초 실패 스텝"을 출력한다.

### 설계 원칙
- **결정성**: 생성 시나리오는 run-unique 마커(`E2E…-${Date.now()}`)를 써 재실행 충돌을 방지하고, 끝에 IndexedDB에서 해당 레코드를 정리(best-effort)한다.
- **하이드레이션 가드**: `goto()`가 `main` 렌더 + networkidle + "DB 초기화 중" 해제까지 대기한다. 이게 없으면 직후 입력/클릭이 React onChange 핸들러 부착 전에 실행돼 누락된다(실제로 복원 업로드에서 발견·수정).
- **안정성**: 3시나리오 × 3연속 실행 그린 확인.

## 확장 백로그 (미구현)

아래 roadmap 시나리오는 다단계 사전 데이터(레시피·식자재·CSV 업로드)가 필요해 fixture/시드 설계가 선행돼야 한다. 하니스는 시나리오 함수만 추가하면 확장되도록 구성됨.

- 메뉴 등록 → 레시피 저장 → 원가마진표 반영 (레시피 구성 UI 다단계)
- 식자재 단가 변경 → 메뉴 원가 → 원가 보고서 (가격 파일 fixture 필요)
- 판매량 업로드 → 미매칭 처리 → 보고서 생성 (판매 CSV fixture 필요)
- 공통원가 → 원가/원산지/알레르기 출력 (출력 파이프라인)
