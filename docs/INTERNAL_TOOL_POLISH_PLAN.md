# 내부 운영툴 추가 보완 계획

작성일: 2026-06-17

## 1. 목적

외부 서비스 전환은 제외하고, 현재 내부 R&D/운영툴로서의 완성도를 더 올리기 위한 후속 작업을 정리한다.

현재 기준 점수는 내부 운영툴 기준 91~92/100점이다. 이 문서의 작업은 서버 DB, 서버 인증, 중앙 백업 같은 외부 SaaS 전환이 아니라, 현재 로컬/LAN 운영 구조 안에서 실사용 안정성과 편의성을 높이는 데 집중한다.

## 2. 목표 점수

- 현재: 91~92/100점
- 1차 목표: 93/100점
- 2차 목표: 94/100점

94점 이상은 자동 테스트뿐 아니라 실제 운영 데이터, Excel/PDF 열람, 대용량 백업/복원 리허설 결과가 쌓여야 가능하다.

## 3. 범위에서 제외

아래 항목은 이번 계획에서 제외한다.

- 서버 DB 전환
- 서버 인증 도입
- HttpOnly/Secure 세션 구조
- 중앙 백업 서버
- 감사 로그 서버 저장
- 외부 고객용 SaaS 배포 준비

위 항목은 별도 아키텍처 전환 프로젝트로 다룬다.

## 4. Claude Code 작업 원칙

각 단계는 아래 순서로 진행한다.

1. 작업 범위 확인
2. 구현
3. 관련 테스트 실행
4. 버그 탐색
5. 사이트 확인
6. 같은 검사를 한 번 더 반복
7. 문서 업데이트
8. 단계별 커밋
9. 다음 단계 이동

### 공통 확인 명령

- `git status --short`
- `git diff --check`
- `npm run lint`
- 관련 Jest 테스트
- `npm run test:ci`
- `npm run audit:docs`
- `npm run qa:smoke`
- 필요 시 `npm run qa:workflow`
- 필요 시 `npm run qa:runtime`
- 필요 시 `npm run build`

### 공통 금지 사항

- 사용자 또는 다른 작업자의 변경을 되돌리지 않는다.
- 여러 큰 작업을 한 커밋에 섞지 않는다.
- 테스트 실패 상태로 커밋하지 않는다.
- 실제 운영 데이터로 삭제, 복원, 초기화 테스트를 바로 하지 않는다.
- 문서 통합 정책을 깨고 중복 계획 문서를 계속 늘리지 않는다.

## 5. 우선순위별 보완 계획

### P0. 실업무 workflow QA 확대

목표: 현재 `qa:workflow` 9개 시나리오를 바탕으로, 원가·공통원가·판매량·영양성분 같은 더 무거운 실업무 흐름을 추가한다.

#### 추가 추천 시나리오

1. 식자재 단가 변경 → 메뉴 레시피 원가 → 원가마진표 반영
2. 공통원가 체크 → 메뉴 원가 → 원산지/알레르기 출력 반영
3. 판매량 업로드 → 미매칭 처리 → 보고서 생성
4. 영양성분 기본값 입력 → 표출력 반영 확인
5. 메뉴 등록 → 레시피 저장 → 원가마진표 반영

#### 2026-06-18 현재 완료된 추가 시나리오

- 브랜드 전환 → 브랜드별 데이터 분리 확인
- 노트 일정 추가 → 캘린더 반영
- 식자재 등록 → 관리 목록 반영

#### 구현 방향

- 기존 `scripts/workflow-qa.mjs`에 단계별 시나리오 함수를 추가한다.
- 공통 대기/토스트/다운로드 helper는 `scripts/workflow-qa-utils.mjs`로 분리한다.
- 테스트 데이터는 run-unique marker로 생성하고 마지막에 정리한다.
- 실제 운영 DB를 직접 오염시키지 않는 방식으로 진행한다.
- 시나리오 실패 시 단계명이 로그에 남아야 한다.

#### 확인 대상 파일

- `scripts/workflow-qa.mjs`
- `scripts/workflow-qa-utils.mjs`
- `__tests__/scripts/workflow-qa-utils.test.mjs`
- `docs/DEFERRED_WORK.md`

#### 테스트 계획

- `npm run qa:workflow`
- `npm run test:ci`
- `npm run qa:smoke`
- 필요 시 `npm run qa:runtime`

#### 완료 기준

- workflow QA가 최소 12개 시나리오를 통과한다.
- 원가, 공통원가, 판매량, 영양성분 중 최소 3개 흐름이 자동화된다.
- 실패 로그가 사람이 바로 읽을 수 있다.

### P1. 운영 QA 실제 실행 기록

목표: 자동 테스트로 잡기 어려운 실사용 리스크를 절차와 결과로 남긴다.

#### 실행 항목

- XLSX 파일을 실제 Excel 앱에서 열어 시트명, 컬럼, 금액 표시를 확인한다.
- PDF/인쇄물에서 긴 표, 페이지 분할, 헤더 반복, 잘림 여부를 확인한다.
- 1천 행, 5천 행, 1만 행 데이터에서 검색/필터 반응성을 확인한다.
- 백업 파일 생성 후 별도 브라우저 context에서 복원 미리보기를 확인한다.
- 실제 메뉴/식자재 샘플 5개 이상으로 원가율을 수동 대조한다.
- 브랜드 전환 후 데이터가 섞이지 않는지 확인한다.

#### 문서화 방식

- 결과는 `docs/DEFERRED_WORK.md`의 운영 QA 섹션에 날짜별로 추가한다.
- 성공/실패/보류를 구분한다.
- 실패 항목은 별도 보류 항목 또는 다음 작업 후보로 등록한다.

#### 완료 기준

- 운영 QA 항목별 실행일과 결과가 남아 있다.
- 자동화가 어려운 리스크가 문서화되어 있다.
- 실패 항목이 방치되지 않고 후속 작업으로 분리된다.

### P2. 식자재 데이터 정리 도구

목표: 실사용 중 누적되는 식자재 중복, 미사용 태그, 단가 누락을 안전하게 정리한다.

#### 작업 항목

- 제품코드 중복 후보 표시
- 유사 식자재 병합 후보 표시
- 미사용 분류/태그 정리 후보 표시
- 분류/태그 이름 변경
- 단가 없는 식자재만 모아 보기
- 단종/전용/범용 상태 일괄 변경 후보 검토

#### 구현 방향

- 바로 병합하지 않고 먼저 진단/미리보기부터 만든다.
- 병합은 undo 또는 사전 백업 안내가 있어야 한다.
- 삭제보다 숨김/정리 후보 표시를 우선한다.
- 데이터 변경 액션은 관리자만 가능해야 한다.

#### 확인 대상 화면

- `/ingredient/manage`
- 식자재 설정 패널
- 식자재 이슈 패널

#### 테스트 계획

- 중복 제품코드 진단 테스트
- 미사용 태그/분류 계산 테스트
- viewer/admin 권한 테스트
- `qa:smoke`

#### 완료 기준

- 식자재 정리 후보를 화면에서 확인할 수 있다.
- 위험 액션 전에 영향 범위가 보인다.
- viewer는 정리/병합/일괄 변경을 실행할 수 없다.

### P3. 출력/다운로드 품질 보강

목표: 보고서, 영양성분, 원산지, 알레르기, 식자재 출력물의 신뢰도를 높인다.

#### 작업 항목

- 파일명 규칙 통일
  - 예: `브랜드명_업무명_YYYY-MM-DD`
- CSV/XLSX 컬럼 순서 고정 테스트
- PDF/인쇄 긴 표 페이지 분할 확인
- 팝업 차단 시 사용자 안내
- 출력 실패 시 toast 또는 화면 안내
- 출력 전 미리보기 상태 점검

#### 확인 대상

- `/report/cost`
- `/report/sales`
- `/report/price`
- `/report/shipment`
- `/nutrition/export`
- `/nutrition/origin`
- `/nutrition/allergen`
- `/ingredient/manage`
- `lib/print/*`
- `lib/report/*`
- `lib/nutrition/label/*`

#### 테스트 계획

- 출력 HTML 구조 테스트
- 파일명 생성 helper 테스트
- XLSX 시트명/컬럼 테스트
- `qa:workflow`에 다운로드 캡처 추가 검토

#### 완료 기준

- 주요 출력물의 파일명과 컬럼 순서가 고정된다.
- 출력 실패가 조용히 묻히지 않는다.
- 실제 출력물 QA 결과가 문서화된다.

### P4. UX 세부 보완

목표: 이미 작동하는 기능을 더 빠르고 덜 헷갈리게 만든다.

#### 작업 항목

- 홈에 오늘 확인할 이슈 요약 강화
- 메뉴마스터 레시피 구성품 복사
- 최근 사용 식자재 추천
- 단가 없는 식자재 빠른 보정 이동
- 원산지/알레르기 영향 미리보기
- 영양성분 부분 누락 기준 정리
- 저장 전 누락 항목 확인 모달 검토

#### 구현 방향

- 한 번에 UI를 크게 바꾸지 않는다.
- 실제 사용 빈도가 높은 입력 흐름부터 개선한다.
- 기존 테스트와 workflow QA를 먼저 보강한 뒤 기능을 넣는다.

#### 완료 기준

- 사용자가 다음 행동을 더 빨리 찾을 수 있다.
- 입력 시간이 줄어든다.
- 기존 저장/출력 결과가 깨지지 않는다.

### P5. 대량 데이터 성능 재검사

목표: 실사용 규모가 커졌을 때 검색/필터/탭 전환이 멈추지 않게 한다.

#### 점검 대상

- 식자재 관리
- 메뉴마스터
- 원가마진표
- 판매량 미매칭
- 보고서 목록
- 제때 단가/출고량 테이블

#### 기준

- 1천 행: 즉시 반응
- 5천 행: 검색/필터 지연이 체감되더라도 화면 freeze 없음
- 1만 행: pagination, debounce, lazy render 필요 여부 판단

#### 테스트 계획

- fixture 기반 대량 데이터 성능 테스트
- 주요 selector memoization 확인
- 브라우저에서 검색/필터/탭 전환 확인

#### 완료 기준

- 성능 문제가 있는 화면과 없는 화면이 구분되어 있다.
- 실제 최적화는 측정 결과가 있는 화면에만 적용한다.
