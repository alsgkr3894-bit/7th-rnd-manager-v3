## 달라진 동작

- 비밀번호 판정·실패 횟수는 서버만 한다. 브라우저에 저장하던 확인값(`v3:auth-hash`)은 지운다.
- 비밀번호 변경은 서버가 현재 비밀번호를 확인하고, 운영 PC(또는 HTTPS)에서만 받는다.
- 인증 상태 파일에 `sessionVersion`, `loginGuard`가 추가된다. 예전 파일과 예전 로그인은 그대로 유효하다.
- 백업 화면의 [RND 업무]는 꺼진 채 시작하고 [전체 선택]에도 들어가지 않는다. 브랜드 백업에도 넣지 않는다.
  빼는 저장소는 파일에 키 자체가 없어, 그 파일을 복원해도 현재 데이터가 남는다.
- 복원 전 임시 백업은 복원 파일에 해당 저장소가 있을 때만(빈 배열 포함) 민감 데이터를 담는다.
- 삭제 전 복구 파일은 지우는 저장소를 그대로 담는다.
- DB 백업을 만들 때와 로그인 직후 자동 백업 때 `F:/7th-rnd-db-backups`에 사본을 맞춘다
  (`.env`의 `DB_BACKUP_COPY_DIR`). 결과는 설정 > 백업의 "다른 드라이브 사본" 칸에 나온다.
  USB가 없으면 폴더를 만들지 않고 "연결 안 됨"으로 표시하며, 원본 백업은 정상 생성된다.
  수동 실행: `npm run db:backup:copy`.

## 확인

임시 DB(11/27 백업 복원, 303,672행)와 시험용 인증 파일을 쓰는 별도 서버에서 확인했다. 서버 쓰기는 거부.

- 로그인(브라우저): 토큰 없는 API 직접 등록 거부, 위조 쿠키 차단·삭제, 5회 실패 후 다른 브라우저·서버
  재시작에도 429, 잠금 만료 뒤 로그인, 비밀번호 변경·전체 해제 시 다른 브라우저 로그아웃, 상태 파일
  손상 안내와 사본 복구 — 전부 통과.
- 콘텐츠 정책: 화면 43개, 인쇄 창, 내려받기, 엑셀 읽기(별도 스레드), IP 조회, 백업·복원에서 위반 0건.
  바깥 연결·스크립트는 차단됨. 개발 서버에서도 화면 이동·HMR 정상.
- 백업: 기본 파일에 시험 비밀번호 없음, 켜면 포함, 기본 파일 복원 후 현재 값 유지, 포함 파일 복원 시
  덮어쓰기 전 임시 백업에 이전 값 보존.
- USB 사본: 14개 3.4GB 28초, 내용(SHA-256) 확인. **USB의 사본**을 임시 DB에 복원해 303,672행·원가 불일치 0.
- 합친 뒤: Jest 3,701개 통과(13개 건너뜀), 문서 감사, 원가 기준값 차이 0건, 실데이터 감사 13개 통과.
  실제 사이트에서 기존 로그인 유지, 위조 쿠키 차단, 새 헤더 확인.

## 작업 중 발생한 문제

- **켜져 있던 사이트가 한 번 꺼졌다.** 합친 직후 설정 파일 변경으로 개발 서버가 다시 시작하는 동안
  `npm install`이 같은 패키지(`caniuse-lite`)를 바꾸고 있어 서버가 종료됐다. 평소 시작 스크립트로 다시
  켰고 데이터 영향은 없다. 패키지를 갱신할 때는 사이트를 먼저 끄거나, 갱신 후 다시 시작해야 한다.

## 남은 것

- **파일 권한**: `.env`, `.runtime-auth.json`, `.db-backups`, `.pgdata`에는 상위 폴더에서 물려받은 수정
  권한이 있고, 그중에 `CodexSandboxUsers` 그룹과 이름이 풀리지 않는 식별자 5개가 있다. 이 계정들은 코드도
  고칠 수 있어, 파일 하나만 막는 것으로는 효과가 제한적이고 Codex 작업이 깨질 수 있어 바꾸지 않았다.
  인증 파일은 저장할 때 새 파일로 교체돼 파일에 건 권한이 풀리므로, 막으려면 권한을 제한한 **폴더**를
  만들고 `RND_AUTH_STATE_PATH`를 그 안으로 지정해야 한다.
- 11/27 이전에 내려받은 전체 백업 파일에는 로그인 정보가 평문으로 있다.
- USB 사본은 암호화하지 않은 DB 덤프다.
- CSP는 인라인 스크립트를 허용한다(nonce 방식은 모든 화면을 요청마다 그려야 해서 보류).
- 보안 감사 로그(점검 P2-12 등)는 5단계 범위가 아니어서 넣지 않았다.
- 확인하지 않은 것: 실제 사용자의 비밀번호 변경·재로그인, 부팅 직후 자동 백업에서의 USB 복사, USB를 실제로
  뺀 상태(폴더가 없는 경우는 자동 테스트), LAN의 다른 PC.
