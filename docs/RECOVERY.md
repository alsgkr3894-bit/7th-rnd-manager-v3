# 백업에서 복구하는 순서

> 2026-11-26 기준. 복원은 되돌릴 수 없으므로 현재 상태를 먼저 백업한다.

## 어떤 백업에 무엇이 있나

| 데이터 | DB 백업 (`.db-backups/*.dump`, 자동) | 브라우저 백업 파일 (`.gz`, 수동) |
|---|---|---|
| 식자재·메뉴·레시피·원가·판매·노트 | 있음 | 있음 |
| 화면 설정(정렬·표시순서·임계값 등) | 있음 (2026-11-26부터 서버에 보관한 설정) | 있음 |
| 외부 로그인정보, 법인카드 | **없음** | 있음 |
| 로그인 비밀번호(`.runtime-auth.json`) | 없음 | 없음 → 새로 설정 |
| `.env`(DB 접속 정보) | 없음 | 없음 → 새로 작성 |

브라우저 백업 파일은 내려받은 뒤 백업 화면의 **[저장한 파일 확인]**까지 해야 믿을 수 있다. 외부 로그인정보가 암호화 없이 들어 있으므로 보관 장소에 주의한다.

## DB 백업이 쓸 만한지 확인

```bash
npm run db:restore:verify
```

임시 DB에 복원해 확인하며 운영 DB는 바꾸지 않는다.

## PC를 새로 설치했거나 DB가 손상됐을 때

1. 프로젝트와 `.postgresql`을 준비하고 `.env`에 `DATABASE_URL`을 새로 적는다.
2. PostgreSQL을 시작한 뒤 **비어 있는** 데이터베이스에 가장 최근 `.dump`를 복원한다. 기존 DB를 덮어쓰기 전에는 반드시 그 상태를 따로 백업한다.

```bash
.postgresql/pgsql/bin/pg_restore.exe -h 127.0.0.1 -p 5432 -U <사용자> -d <빈 DB 이름> --no-owner --no-privileges --exit-on-error .db-backups/<백업>.dump
```

3. 앱을 시작하고 **운영 PC의 브라우저(`127.0.0.1`)**에서 연다. 인증 파일이 없으면 **이때 처음 입력하는 비밀번호가 새 비밀번호**가 된다(화면 제목이 "비밀번호 설정" 또는 "로그인"으로 보일 수 있다). 다른 사람이 접속하기 전에 바로 설정한다.
4. 설정 / 백업 → **서버 데이터 불러오기**를 실행한다. 업무 데이터와 화면 설정이 내려온다(데이터 30만 행 기준 약 5분).
5. 외부 로그인정보·법인카드를 되돌리려면 설정 / 백업 → **데이터 복원**에서 최근 브라우저 백업 파일을 고르고 **"RND 업무" 모듈만** 선택해 복원한다. 다른 모듈까지 고르면 그 파일의 시점으로 덮어쓴다. 모듈 하나만 골라도 파일에 담긴 **화면 설정(정렬·표시순서 등)은 함께 적용**되므로, 4번에서 받은 설정보다 오래된 파일이면 복원 뒤 다시 확인한다.
6. 식자재·메뉴·레시피·원가 화면을 열어 확인한다.

## 비밀번호를 잊었거나 인증 파일이 손상됐을 때

1. 앱을 멈춘다.
2. `.runtime-auth.json`의 이름을 바꿔 둔다(바로 지우지 않는다).
3. 앱을 다시 시작해 운영 PC의 `127.0.0.1` 주소로 열고 새 비밀번호를 입력한다. 인증 파일이 없는 상태에서 처음 입력한 값이 새 비밀번호가 된다("로그인" 화면으로 보여도 같다). 업무 데이터는 바뀌지 않는다.
4. 로그인 시도 제한(15분)이 걸려 있으면 기다린 뒤 시도한다.

## 방금 대량 삭제한 것을 되돌릴 때

초기화·전체 삭제·DB 재생성은 지우기 전에 `삭제전복구_<대상>_<날짜>.gz` 파일을 내려받는다. 설정 / 백업 → **데이터 복원**에서 그 파일을 고르고 해당 모듈을 선택하면, **파일에 담긴 저장소만** 그 시점으로 돌아간다.

## 서버에 아직 보내지 못한 변경

서버나 PostgreSQL이 내려간 동안의 저장은 그 브라우저에 보관돼, 서버가 돌아오면(또는 다음에 앱을 열면) 자동으로 전송된다. 설정 / 백업 → 서버 데이터 불러오기 화면에서 남은 건수를 볼 수 있다. **그 전에 브라우저 데이터를 지우면 서버에 가지 못한 변경은 사라진다.**
