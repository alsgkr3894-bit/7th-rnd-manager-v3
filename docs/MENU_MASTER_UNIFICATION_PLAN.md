# 메뉴마스터 통합 계획

작성: 2026-06-15  
상태: 계획 정리  
전제: 구형 레시피 데이터는 이관하지 않아도 되며, 필요한 데이터는 새 기준으로 다시 입력한다.

---

## 1. 결정 요약

메뉴마스터, 레시피마스터, 원가레시피는 사용자 관점에서 하나의 흐름으로 합친다.

최종 구조는 **메뉴마스터를 단일 진입점**으로 두고, 메뉴별 상세 안에서 기본정보, 판매가, 레시피, 원가 계산 결과를 함께 관리하는 방식이다.

```text
메뉴마스터
 ├─ 메뉴 기본정보
 ├─ 판매가
 ├─ 레시피
 ├─ 원가 자동계산
 └─ 원산지/알레르기/영양 연결
```

현재 별도 메뉴로 보이는 레시피마스터와 원가레시피는 장기적으로 메뉴마스터 안으로 흡수한다.

---

## 2. 현재 문제

현재 메뉴 관련 데이터 입력 흐름은 기능별로 나뉘어 있다.

```text
메뉴마스터
레시피마스터
원가레시피
재료 단가표
원가마진표
영양성분/원산지/알레르기
```

이 구조에서는 사용자가 메뉴 하나를 만들 때 다음 질문이 생긴다.

- 메뉴는 어디서 만들고, 레시피는 어디서 입력해야 하는가?
- 레시피마스터와 원가레시피 중 어느 쪽이 실제 기준인가?
- 원가마진표, 원산지, 알레르기, 제품별 사용현황이 같은 레시피를 보고 있는가?

구형 데이터 유지가 필요 없다면, 이 복잡도를 계속 가져갈 이유가 적다.

---

## 3. 목표 구조

### 3.1 사용자 화면 기준

```text
/menu-master
 ├─ 메뉴 목록
 ├─ 메뉴 추가/수정
 └─ 메뉴 상세
     ├─ 기본정보
     ├─ 판매가
     ├─ 레시피
     ├─ 원가 계산
     └─ 영양/원산지/알레르기 연결 상태
```

### 3.2 유지할 화면

| 화면 | 방향 |
|------|------|
| `/menu-master` | 메인 메뉴 관리 화면으로 유지 |
| `/cost/margin` | 원가마진표 결과/분석 화면으로 유지 |
| `/cost/ingredient-price` | 식자재 단가 마스터로 유지 |
| `/nutrition/*` | 메뉴마스터와 레시피 기준을 읽는 출력/관리 화면으로 유지 |

### 3.3 축소 또는 제거할 화면

| 화면 | 방향 |
|------|------|
| `/cost/recipe-master` | 메뉴마스터 상세의 레시피 영역으로 흡수 |
| `/cost/recipe` | 제거하거나 공통묶음/엣지 관리만 남김 |
| 기존 구형 레시피 입력 UI | 새 기준 입력 완료 후 제거 |

---

## 4. 데이터 기준

### 4.1 메뉴 기본정보

메뉴 기준은 `menu_master`가 가진다.

```text
menu_master
  - menuCode
  - menuName
  - category
  - size
  - price
  - status
  - displayOrder
  - hidden
  - excludeFromOrigin
```

### 4.2 새 레시피 기준

구형 `cost_recipes`와 카테고리별 상세 레시피를 계속 병행하지 않고, 새 기준 저장소 하나로 단순화하는 방향이 좋다.

예상 형태:

```text
menu_recipes
  - id
  - menuCode
  - components[]
      - productCode
      - ingredientName
      - quantity
      - unit
      - unitPriceSnapshot
      - note
  - updatedAt
```

핵심은 모든 후속 화면이 `menuCode` 기준으로 같은 레시피를 읽는 것이다.

```text
menu_master + menu_recipes
 → 원가마진표
 → 제품별 사용현황
 → 원산지 정보
 → 알레르기 정보
 → 영양 자동계산
 → 표 출력
```

---

## 5. 구현 단계

### Phase 1. 메뉴마스터 상세 구조 만들기

- 메뉴마스터에서 메뉴를 선택하면 상세 영역을 연다.
- 상세 안에 기본정보, 판매가, 레시피, 원가 계산 탭을 둔다.
- 기존 메뉴마스터 목록은 유지한다.
- 레시피 입력은 메뉴 상세 안에서 가능하게 한다.

완료 기준:

- 메뉴 하나를 만들고 같은 화면에서 레시피까지 입력할 수 있다.
- 사용자는 레시피마스터 화면으로 이동하지 않아도 된다.

### Phase 2. 새 레시피 저장소 도입

- 새 `menu_recipes` 저장소 또는 동등한 단일 레시피 기준을 만든다.
- 메뉴코드 1개당 레시피 1개를 기본 정책으로 둔다.
- 피자, 1인피자, 사이드, 세트 모두 같은 레시피 구조를 사용한다.
- 카테고리별 차이는 UI와 계산 표시에서만 처리한다.

완료 기준:

- 새로 입력한 메뉴/레시피는 구형 `cost_recipes` 또는 카테고리별 상세 store에 의존하지 않는다.

### Phase 3. 계산/출력 화면 연결 변경

아래 화면들이 새 기준을 읽도록 정리한다.

- 원가마진표
- 제품별 사용현황
- 원산지 정보
- 알레르기 정보
- 영양 자동계산
- 영양/원산지 표 출력

완료 기준:

- 같은 메뉴의 레시피가 화면마다 다르게 보이지 않는다.
- 식자재 사용 메뉴 수, 원산지, 알레르기, 원가가 같은 레시피 기준으로 계산된다.

### Phase 4. 기존 화면 정리

- `/cost/recipe-master`는 `/menu-master` 또는 메뉴 상세로 이동시킨다.
- `/cost/recipe`는 제거하거나 공통묶음/엣지 관리만 남긴다.
- 사이드바에서 중복 메뉴를 제거한다.

완료 기준:

- 메뉴 생성과 레시피 입력의 진입점이 하나다.
- 사용자가 "어디서 레시피를 입력해야 하는지" 헷갈리지 않는다.

### Phase 5. 구형 코드 정리

전제상 구형 데이터는 새로 입력 가능하므로, 이관보다 제거를 우선한다.

- 구형 레시피 fallback 제거
- detail recipe store 병행 로직 제거
- 중복 매핑 함수 정리
- 테스트는 새 기준 중심으로 재작성

완료 기준:

- 원가/영양/원산지/알레르기/사용현황이 단일 레시피 기준만 사용한다.

## 6. 새 화면 UX 초안

```text
메뉴마스터

[검색] [카테고리] [상태] [메뉴 추가]

메뉴 목록
 ├─ 슈퍼콤비네이션 L
 ├─ 슈퍼콤비네이션 R
 └─ 치킨바사삭

선택 메뉴 상세
 ├─ 기본정보
 │   ├─ 메뉴코드
 │   ├─ 메뉴명
 │   ├─ 카테고리
 │   ├─ 사이즈
 │   └─ 상태
 ├─ 판매가
 │   └─ 판매가 입력
 ├─ 레시피
 │   ├─ 식자재 검색/추가
 │   ├─ 사용량 입력
 │   └─ 단가 자동 반영
 ├─ 원가
 │   ├─ 총 원가
 │   ├─ 원가율
 │   └─ 마진
 └─ 연결 상태
     ├─ 원산지 누락
     ├─ 알레르기 누락
     └─ 영양값 누락
```

---

## 7. 정책 메모

### 7.1 메뉴코드

- 메뉴코드는 모든 연결의 기준이다.
- 메뉴명 변경은 허용하되, 메뉴코드는 가능한 한 유지한다.
- 메뉴코드를 변경할 경우 연결된 레시피/영양/출력 데이터도 함께 갱신해야 한다.

### 7.2 판매가

- 판매가는 메뉴마스터 안에서 관리한다.
- 원가마진표는 메뉴마스터의 판매가를 읽는다.
- 별도 판매가 mirror가 필요하다면 내부 호환용으로만 유지한다.

### 7.3 레시피

- 새 기준에서는 메뉴 1개당 레시피 1개를 원칙으로 한다.
- L/R처럼 사이즈가 다른 메뉴는 메뉴코드가 다르면 별도 레시피로 본다.
- 공통묶음/엣지는 나중에 필요하면 별도 보조 기능으로 추가한다.

### 7.4 구형 데이터

- 구형 데이터는 이관 대상이 아니다.
- 기존 레시피가 사라져도 운영상 새로 입력 가능하다는 전제로 진행한다.
- 구현 중 임시 fallback은 둘 수 있지만, 최종 목표는 제거다.

---

## 8. 기대 효과

- 메뉴 생성부터 원가 확인까지 한 화면 흐름으로 정리된다.
- 레시피 기준이 하나로 고정된다.
- 원가마진표, 제품별 사용현황, 원산지, 알레르기, 영양 출력의 결과 불일치가 줄어든다.
- 신규 사용자나 운영자가 메뉴 구조를 이해하기 쉬워진다.
- 구형 호환 로직을 줄여 유지보수가 쉬워진다.

---

## 9. 우선순위

1. 메뉴마스터 상세에 레시피 입력 붙이기
2. 새 단일 레시피 기준 만들기
3. 원가마진표를 새 기준으로 연결
4. 원산지/알레르기/사용현황을 새 기준으로 연결
5. 레시피마스터/원가레시피 중복 메뉴 제거
6. 구형 레시피 fallback 제거

---

## 10. 최종 목표

최종적으로 사용자는 다음 흐름만 기억하면 된다.

```text
메뉴마스터에서 메뉴를 만든다.
그 메뉴 안에서 레시피를 입력한다.
원가, 원산지, 알레르기, 영양 출력은 자동으로 따라온다.
```
