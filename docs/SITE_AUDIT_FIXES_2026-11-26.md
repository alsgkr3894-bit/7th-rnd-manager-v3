## 2. 사용 방식이 달라지는 점

- **백업:** 내려받은 뒤 백업 화면의 **[저장한 파일 확인]**으로 그 파일을 골라야 백업 경고가 해제된다. 이 변경 전에 쌓인 이력은 확인된 것으로 본다.
- **복원:** 복원이 중단되거나 일부만 적용되면 모든 업무 화면 상단에 경고가 뜬다. 복원 화면에서 **[확인 완료]**를 해야 사라진다.
- **노트 수정:** 저장하지 않은 변경은 상태·평점 등 어떤 항목이든 다시 열 때 복구 안내가 나온다. 이전에 남아 있던 임시저장이 있으면 처음 한 번 안내가 뜰 수 있다.

## 3. 항목별 구현

### 1. 로그인 화면 분리

- `components/AppShell.jsx`를 `AuthShell`(브라우저 설정 적용만)과 `WorkShell`로 나눴다. 경로가 `/login`이면 `AuthShell`만 마운트한다.
- 결과: 비로그인 `/login`의 API 요청은 `GET /api/auth/session` 1건이고 `/api/db/*`는 0건이다.

### 2. 임시저장 실패 표시

- `lib/note/storage.js`의 `setJSONLS`·`saveDraft`가 저장 성공 여부를 돌려준다.
- `app/note/write/useNoteWriteDraftAutosave.js`는 실패하면 `error` 상태를 유지하고 `retryDraftSave`를 제공한다.
- 화면: "임시저장 실패 — 저장 공간을 확인해 주세요 [다시 시도]". 입력 내용은 그대로 남는다.

### 3. 초안 복구 안내

- `hasStoredNoteDraft`가 임시저장과 같은 범위(사진·id·시각 제외한 전체 항목)를 비교한다.
- 정식 저장 때 예약된 임시저장을 취소한 뒤 초안을 지운다. 지운 초안이 다시 써지는 경로를 막았다.

### 4. 삭제 실행취소 (범위 축소)

- 문서의 "식자재와 알레르기 연결을 한 트랜잭션으로 복원"은 대상 store `nutrition_allergy_links`가 DB v20에서 삭제돼 **구현하지 않았다.**
- 일괄 실행취소가 일부 실패하면 제품코드(없으면 식자재명)를 최대 5개까지 알리고 목록을 다시 읽는다 (`app/ingredient/manage/ingredientManageUtils.js`).

### 5. 식자재 이슈 배지

- `hooks/usePageStats.js`는 집계가 실패해도 마지막 성공 건수를 유지하고 `ingredientIssueFailed`를 켠다. 다른 배지 조회와 분리했다.
- 알림: 실패하면 "갱신 실패"와 마지막 건수, 한 번도 못 읽었으면 "식자재관리 이슈 확인 필요".

### 6. 홈 새로고침

- 새로고침 버튼과 탭 복귀가 같은 `refreshDashboard`를 쓴다. 월을 골랐으면 그 월의 판매 통계까지 읽는다.
- 결과를 완료·부분 갱신(실패 개수)·실패로 안내한다 (`lib/home/refresh-summary.js`).
- 늦게 끝난 이전 기간 또는 최신 월의 결과는 선택한 기간을 덮지 않는다.
- 한계: 조회 함수가 내부에서 오류를 삼키고 빈 값을 돌려주면 실패로 세지 못한다.

### 7. DB 상태·백업 목록

- 두 조회를 `Promise.allSettled`로 나누고 각각 오류와 마지막 확인 시각을 둔다.
- 표시 값은 `app/settings/backup/panels/serverBackupView.js`에서 만든다. 백업 개수는 목록 조회가 성공했을 때만 보여 준다.

### 8. 백업 이력

- 이력 항목에 `exportedAt`, `fileRows`, `fileCheckedAt`을 추가했다. `at`은 다운로드를 요청한 시각이다.
- 파일 확인(`lib/backup/file-check.js`)은 JSON 읽기, 백업 형식, 빠진 store 유무, 내보낸 시각, 전체 행 수를 대조한다. **DB 복원 검증은 아니다.**
- 백업 경고는 파일이 확인된 백업을 **내보낸 시점**부터 센다. 오래된 파일을 지금 확인해도 날짜가 새로워지지 않는다.
- 홈의 인사말·할 일·데이터 신선도에 "백업 파일 확인 전" 상태를 반영했다.
- 이력이 늘거나 확인하면 배너와 마지막 시각을 함께 다시 계산한다.
- **제외:** "임시 DB 복원 성공 시각"은 그런 복원 기능이 없어 기록하지 않는다. 10번 작업에서 다룬다.

### 9. 복원 일지 안내

- `lib/backup/restore-journal.js`가 확인이 필요한 상태(`running`, `running_group`, `failed_partial`, `completed_with_errors`)를 판정한다. 이 탭에서 진행 중인 복원은 제외한다.
- 일지에 복원한 파일 이름과 복원 직전 자동 백업 이름을 남긴다.
- 확인 전에 다른 복원이 일지를 덮어써도 이전 경고를 `unresolved`로 보존한다.
- 상단 배너(`RestoreJournalNotice`)와 복원 화면 카드에 적용·실패 부분과 복구 절차를 보여 준다. 배너는 인쇄에서 숨긴다.
- 편집을 강제로 막지는 않는다.

### 추가. `getAll` 처리되지 않은 오류

- 재검토의 실패 주입 중에 발견했다. `lib/db/crud.js`의 `request.finally()`가 실패를 이어받은 새 Promise를 만들었다. `then(forget, forget)`으로 바꿨다.
